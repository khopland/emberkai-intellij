## Taking new screenshots

```sh
./gradlew screenshots                 # every editor capture
./gradlew screenshotEmberkaiLight     # one capture
./gradlew marketplaceScreenshots      # 16:10 Marketplace media in docs/marketplace
```

Each capture starts the development IDE with a fresh profile on a copy of the
sample project outside Git, so no branch name or author hints appear. A startup
script selects the theme, editor scheme, and spacing and sizes the window to
1400 × 1000 points. When code analysis has finished, the IDE paints its window
into `docs/screenshots/<name>.png`. Captures never include the mouse pointer,
tooltips, or other windows, and take about 30 seconds each. The list of
captures is in `build.gradle.kts`.

On a 2x display the images are 2800 × 2000 pixels. On a 1x display, such as Xvfb,
add `-PscreenshotScale=2`. The **Screenshots** workflow does this on Linux for
pull requests that change the themes, schemes, or samples, and uploads the
images as an artifact for review. Commit captures from macOS so the gallery
keeps the same font rendering.

The diff viewer, console, and semantic highlighting captures are still taken by
hand. Use an isolated development IDE profile and the sample project, keep the
same editor size and spacing, dismiss tooltips and popups, and wait for code
analysis or sample execution to finish. Check the saved PNG for the mouse
pointer before adding it here.
